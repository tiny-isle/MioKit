# 使用场景

下面的例子可以按自己的节点替换。文件、文件夹可直接拖入收录；涉及剪贴板、快速输入、终端等插件功能时，先安装并运行相应插件，再从节点选择器中选择实际提供的可执行节点。

| --- | --- |
| 把一个项目的入口收在一起 | [项目开工](#场景一每天打开同一个项目) |
| 换软件时自动换工具 | [应用专属主面板](#场景二切换软件时自动换一组动作) |
| 用鼠标看菜单后选动作 | [鼠标旁的轮盘](#场景三阅读和资料整理时鼠标不用离开当前位置) |

| 多个软件共用一套资料工具 | [关联程序](#场景七多个阅读软件共用资料工具) |

先用一个能观察结果的文件夹节点测试，确认入口可用，再换成自己需要的动作。示例中自行选择的按钮与修饰键会明确说明，不代表默认配置。

## 场景一：每天打开同一个项目

**需求：** 代码编辑器、项目目录和需求文档分散在不同位置，每天要逐个查找。

1. 按默认快捷键 `Ctrl + Space` 呼出启动窗，创建“项目 A”分类。
2. 从资源管理器一次拖入项目目录和文档，确认名称与路径，保存添加。
3. 从节点面板拖入编辑器节点，按使用顺序排列。
4. 在 **启动窗设置** 中检查 **记住上次分类**，需要时再修改呼出快捷键。
5. 如果每天都要一起打开它们，在 **快速启动 → 自定义启动** 创建“项目 A 开工”组合，并添加到分类。

**使用时：** 呼出启动窗后单独点选需要的内容，或点击组合一起发起启动。临时项目可继续新增分类，不必把所有图标挤在一起。

详见：[启动窗](launcher.md) · [启动组合](quick-launch.md#创建启动组合)

## 场景二：切换软件时自动换一组动作

**需求：** 编辑代码和整理资料时，需要不同的工具，但希望用同一种方式呼出。

1. 在主面板全局区放项目目录和常用工具节点。
2. 在通用区放其他软件中常用的节点。
3. 添加代码编辑器的应用配置，选择它的运行进程。
4. 在代码编辑器的专属区放项目文档、终端或开发工具节点。
5. 给主面板配置一个中键组合，例如 `Ctrl + 中键`，并保存。

**使用时：** 在编辑器中呼出，下方显示开发动作；在未配置的软件中呼出，下方显示通用动作，上方全局入口继续可用。

配置多个项目时，可以在相应区域新增“项目 A”“项目 B”动作页，再通过分页按钮切换。按应用匹配依据进程，区分同一软件里的不同项目时，应主动使用动作页整理。

详见：[主面板](main-panel.md) · [应用专属配置](actions.md#添加应用专属配置)

## 场景三：阅读和资料整理时，鼠标不用离开当前位置

**需求：** 经常需要打开资料目录、查看剪贴板或调用输入工具，不想每次都敲名称搜索。

1. 在全局轮盘中保留一圈，把少量常用节点放在容易记住的方向。
2. 选择侧键 X2 作为触发按钮，保存设置。
3. 把低频动作收进“更多工具”子轮盘，减少主轮盘拥挤。
4. 若某个阅读软件需要特殊工具，为它添加应用绑定，只覆盖相应扇区。

**使用时：** 按住 X2 拖动呼出，观察高亮后松开执行。面对不同资料可以选不同工具，无需提前记住很多手势。

详见：[轮盘](radial-menu.md) · [子轮盘](radial-menu.md#用子轮盘整理更多动作)

## 场景四：把两个高频操作变成手势

**需求：** 已经明确要执行哪个动作，希望少一步点选。

1. 在手势基础设置中选择侧键 X1 并启用。
2. 从内置手势中选一条简单轨迹，绑定项目目录。
3. 再选另一条明显不同的轨迹，绑定常用插件节点。
4. 在手势属性中使用识别测试，确认轨迹容易区分。
5. 熟练后，再为第一条轨迹添加 `Ctrl` 组合，绑定项目文档。

**使用时：** 按住 X1 画完轨迹，松开执行；需要文档时，同时按住 Ctrl 绘制对应轨迹。尚未绑定的手势不会自动执行浏览器前进、后退等操作。

详见：[鼠标手势](mouse-gestures.md)

## 场景五：让键盘鼠标各司其职

多种入口可以同时使用，同一个节点按频率安排到不同位置：

| 使用频率或情境 | 建议入口 | 示例 |
| --- | --- | --- |
| 临时查找 | 搜索框 | 找一个偶尔使用的应用或系统设置 |
| 成组收纳 | 启动窗 | 项目分类中的应用、目录、文档 |
| 看当前软件选择动作 | 主面板 | 编辑器的开发工具区、其他软件的通用区 |
| 鼠标附近选一个动作 | 轮盘 | 资料目录、剪贴板、更多工具 |
| 已经记住的动作 | 手势或节点快捷键 | 打开高频目录、调用常用输入节点 |

可以先采用下面的触发分工，再根据自己的鼠标和快捷键占用情况调整：

| 功能 | 一套可自行配置的示例 |
| --- | --- |
| 搜索框 | `Alt + Space` |
| 主面板 | `Ctrl + 中键` |
| 轮盘 | 侧键 X2 |
| 鼠标手势 | 侧键 X1 |
| 启动窗 | 默认 `Ctrl + Space`，需要时到启动窗设置修改 |

以上鼠标分工是配置示例，不代表默认值。鼠标没有侧键时，可以在各模块中重新选择触发方式，逐个测试，避免多个功能争用同一按钮。

## 场景六：边整理边验证一套新布局

1. 打开节点面板，搜索并拖出需要的节点。
2. 先填主面板的全局格子，把面板钉住，连续执行检查。
3. 再将同一批节点拖到轮盘扇区或手势行，减少重复查找。
4. 在绑定属性中给长名称起一个短显示名，点击保存。
5. 用可用的撤销、重做调整绑定；本地文件通过拖入新收录后，即使撤销绑定，节点仍在启动库中。

**使用时：** 一边尝试一边调整位置，不必重新创建节点；确认布局顺手后，再添加应用专属覆盖。

## 场景七：多个阅读软件共用资料工具

**需求：** 浏览器、PDF 阅读器和电子书软件中常用同一组目录和插件工具，不想分别配置。

1. 打开动作配置，添加“资料阅读”应用配置，把最常用阅读软件的进程设为匹配进程。
2. 使用 **选择关联程序** 加入其他需要共用工具的软件。
3. 为这组应用配置轮盘扇区或手势组合，绑定资料目录和当前已安装插件的可执行节点。
4. 分别切到这些软件，使用相同触发方式检查动作。

**使用时：** 这几个软件使用同一套配置。以后某个软件需要独立动作时，为它建立直接匹配的配置，独立配置会优先；添加时如提示进程已归属，先调整原配置。

详见：[应用专属配置](actions.md#添加应用专属配置)

## 场景八：手势不确定时先看候选

**需求：** 刚开始使用手势，希望执行前先看到动作名称，避免凭感觉松开。

1. 先给两条容易区分的手势绑定不同文件夹节点，保存配置。
2. 切回日常软件，按住手势触发按钮绘制其中一条。
3. 画完继续按住并停顿，等待候选卡片出现。
4. 看清动作名称，把指针移到对应卡片上，再松开执行。

**使用时：** 想取消就按 `Esc`，或在候选卡片外松开。熟悉之后再尝试直接绘制后松开；直接执行仍需要最佳候选达到设置的执行阈值。

详见：[停顿后选择候选](mouse-gestures.md#停顿后选择候选)

## 检查这套配置是否顺手

- 在普通桌面环境试一次，再到目标软件中试一次，确认应用匹配正确。
- 每个入口先调用一个熟悉的文件夹，验证后再添加插件动作或组合。
- 鼠标功能争用同一按钮时，先分别测试，再调整按钮与修饰键分工。
- 清除应用专属的轮盘或手势绑定后，检查是否回退到了全局同项。
- 配置基础设置、显示名称或手势样本后，按对应窗口保存，再重新触发验证。
