# MioKit 完整使用场景

这些场景以明确任务组织功能，包含准备、配置、日常使用与结果检查。文件夹和文档换成自己的路径；涉及插件时先安装并运行，完成插件要求的首次设置或内容创建。

首次尝试可以只使用一个文件夹节点，确认操作闭环后再添加更多功能。文中的 X2、Ctrl + 中键等安排为自行配置示例，不代表默认值。

## 场景一：每天打开同一个项目

**当前问题：** 编辑器、项目目录和需求文档散在不同位置，每天需要重复查找。

**准备内容：** 已安装编辑器、一个项目目录和一份能直接打开的文档。

1. 按 `Ctrl + Space` 打开启动窗，添加“项目 A”分类。
2. 从资源管理器一次拖入项目目录和文档，新路径检查后保存添加。
3. 打开节点面板，将编辑器节点拖入同一分类。
4. 将最常用项目拖到前面，需要时缩短显示名称。
5. 到自定义启动创建“项目 A 开工”组合，选择这些已收录成员，再把组合放入分类。

**日常使用：** 呼出启动窗，点击单个内容，或点击组合一起发起启动。临时连续点选时钉住窗口，完成后隐藏。

**检查结果：** 单项分别能打开，组合能发起所选成员。组合不保证完成顺序，不能要求编辑器先完全启动再开文档。

## 场景二：切换软件时自动换工具

**当前问题：** 编辑器和阅读软件所需工具不同，但想用相同方式呼出。

1. 按中键打开主面板，全局区添加项目目录和常用工具。
2. 在通用区放未配置软件时需要的动作。
3. 打开动作配置，添加编辑器应用，选择匹配进程，建立“项目”动作页。
4. 该页添加项目文档、终端工具等当前可用节点。
5. 按需要给阅读软件建立另一组动作。

**日常使用：** 将鼠标放进目标软件窗口按中键，下方显示对应工具，上方全局入口保留。按键盘快捷键呼出时先激活目标软件。

**检查结果：** 编辑器、阅读软件和未配置程序中分别测试。未匹配时使用通用内容，应用专属页不会自动叠加通用区。

## 场景三：阅读时在鼠标附近选择工具

**当前问题：** 打开资料目录、调用插件工具等操作频繁，但每次选择的内容不同，不想记多条轨迹。

1. 在轮盘基础设置建立一圈，保留少量容易辨认的槽位。
2. 将触发按钮自行改为 X2，保存设置。
3. 全局轮盘加入资料目录、常用文档和已安装插件的工具节点。
4. 建立“更多工具”子轮盘，将低频节点放入，主轮盘保留入口。

**日常使用：** 在阅读窗口内按住 X2 拖动，指向高亮位置后松开；进入子轮盘后用左键点击动作。

**检查结果：** 中心取消、Esc 取消均可用。不要用拖出轮盘图形外作为取消方式，因为外侧方向仍可能命中。

## 场景四：把两个固定动作记在手上

**当前问题：** 每天反复打开同一目录和文档，希望少一次看菜单选择。

1. 在手势全局绑定中选择内置 **上**，无修饰键行绑定项目目录。
2. 为 `Ctrl + 上` 绑定需求文档。
3. 使用手势属性中的识别测试确认轨迹清楚，再回目标软件实际触发。

**日常使用：** 默认按住 X1 向上画完松开，打开目录。需要文档时先按 Ctrl，再按 X1 开始绘制，最后松开鼠标。

**检查结果：** 两种组合分别执行正确动作。中途补按 Ctrl 不改变本次组合，没有绑定的组合也不会自动改用无修饰键动作。

## 场景五：还不熟练时先看手势候选

**当前问题：** 已绑定动作，但不确定这次绘制会识别成哪条轨迹。

1. 给容易区分的两条手势绑定不同的可观察目录节点。
2. 按住手势按钮画完后保持按住并停止移动。
3. 等待候选卡片，查看动作名、轨迹名和匹配度。
4. 将指针移到需要的卡片上，松开执行。

**日常使用：** 不确定时先看候选，熟悉后直接画完松开。候选出现后的移动用于选卡片，不继续添加轨迹。

**检查结果：** 在卡片外松开或按 Esc 不执行，指向已绑定动作的卡片后才执行。主动选择与自动执行阈值的适用范围不同。

## 场景六：多个阅读软件共用一套资料动作

**当前问题：** PDF 阅读器、电子书软件和浏览器都需要同一资料目录与输入工具。

1. 添加“资料阅读”应用资料，选择一个主要匹配进程。
2. 通过关联程序加入其他需要共用的软件。
3. 为这组配置设置轮盘或手势动作，不必分别重复绑定。
4. 在每个软件窗口内分别触发测试。

**日常使用：** 三个软件共用工具，实际操作目标仍是本次触发的软件。以后某个软件需要独立工具时，为它建立直接匹配配置，直接匹配优先。

**检查结果：** 相同进程不能作为两组直接匹配，同一关联程序不能重复归属。遇到归属提示时编辑旧配置，不重复添加。

## 场景七：集中管理便携软件

**当前问题：** 多个便携程序没有安装到系统菜单，搜索时找不到。

1. 到 **快速启动 → 扫描配置** 添加实际存放程序的目录。
2. 程序在子文件夹中时，添加放置 `.exe` 的那个文件夹。
3. 按需要添加排除关键词，例如“卸载”，确认不会误排除需要的名称。
4. 点击重新扫描，到应用扫描列表查找并启动。
5. 为名称难记的程序设置别名，频繁使用的加入分类或面板。

**日常使用：** 通过搜索别名启动，或从项目分类调用。只想打开软件目录本身时另建文件夹启动项。

**检查结果：** `.exe` 只扫描配置目录第一层，不能将一个顶层目录理解为递归收录所有子目录中的程序，更不能当成文档全盘索引。

## 场景八：钉住面板，一边查看一边切换工作

**当前问题：** 希望面板保持可见，同时能够切换软件查资料。

1. 打开主面板并钉住，暂停自动隐藏。
2. 未锁定场景时切换软件，观察应用区是否跟随更新。
3. 临时需要保留某组格子时锁定该场景。
4. 需要恢复自动切换时选择 **自动匹配当前应用**。

**日常使用：** 钉住控制面板是否保持显示，锁定控制显示哪组格子。输入类动作仍应确认当前目标。

**检查结果：** 固定工具组不表示固定输入窗口；不能因为场景名还显示编辑器，就向已经切换走的编辑器假设性输入。

## 场景九：文件搬家后修正入口

**当前问题：** 项目目录移动后，启动窗、主面板和轮盘中的旧节点都打不开。

1. 在 **自定义启动** 找到原项，先点击启动确认错误。
2. 编辑同一个启动项，通过浏览按钮选择新路径，保存。
3. 在列表再次启动，再回各入口分别测试。
4. 若原节点已经删除，则用新节点替换失效绑定；无需反复移动旧图标。

**日常使用：** 原内容由快速启动维护，入口布局在各自窗口维护。文件改位置优先修正原项，减少同名重复内容。

## 一套可自行配置的入口分工

| 任务 | 配置示例 | 作用 |
| --- | --- | --- |
| 临时查找 | 搜索框保留 Alt + Space | 按名称找到内容 |
| 项目收纳 | 启动窗保留 Ctrl + Space | 分类点选 |
| 软件工具面板 | 主面板改为 Ctrl + 中键 | 查看全局与应用动作 |
| 看方向选择 | 轮盘改为 X2 | 鼠标附近点选 |
| 熟悉轨迹执行 | 手势保留 X1 | 高频动作调用 |

默认主面板是单独中键，默认轮盘是右键；表中的修改需要自己到配置中保存。按钮较少时，先启用最需要的功能逐一测试，不必一次开启所有使用方式。
