# 架构原则

> 状态：设计规范草案，不代表已经发布的插件 API。

本页记录 MioKit 及其插件生态需要遵守的架构方向。具体项目名称、接口签名和程序集划分会随着 SDK 实现确定后补充。

## 分层边界

预期的职责分层如下：

- **Contracts**：放置接口、选项和事件等稳定契约。
- **Core**：放置通信逻辑、核心业务、ViewModel 和脚本编排。
- **Infrastructure**：放置存储等具体实现。
- **UI Hosts**：放置 Avalonia、WPF 或其他宿主相关的界面和平台服务。

依赖方向应保持为：

```text
UI Hosts -> Core -> Contracts
UI Hosts -> Infrastructure -> Contracts
```

Core 不应依赖具体宿主框架类型。

## 依赖注入

- 使用构造函数注入。
- ViewModel 依赖接口，而不是具体适配器。
- 注册集中在对应模块中，避免在业务代码中隐藏创建依赖。
- 插件能力通过小而明确的接口提供，避免一个聚合接口承载所有 UI 行为。

## UI 解耦

核心通信和插件契约应保持 UI 无关。日志、消息缓冲、流量统计和视口等能力应以聚焦的接口注入，而不是把整个 UI 对象传入 Core。

## 脚本与存储

- 脚本管理通过脚本管理抽象完成。
- 脚本持久化通过脚本存储抽象完成。
- 应用配置持久化通过配置存储抽象完成。
- LiteDB 或其他具体存储引擎类型只能位于 Infrastructure，不应泄漏到 Contracts 或 Core ViewModel。

## 多宿主支持

核心实现应尽量在 Avalonia 和 WPF 等宿主之间共享。宿主可以按通信模式或平台能力拆分，但核心业务规则和插件契约应保持统一。

## API 稳定性

本页描述的是设计方向。正式接口发布后，需要为每个公共接口补充适用版本、线程模型、错误处理和兼容性说明。
